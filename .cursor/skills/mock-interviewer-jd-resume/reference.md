# 模拟面试参考（材料清单 + 追问池 + 职级差异）

## 开场前向用户确认

- **材料**：优先读取工作区根目录 `jd.md`、`resume.md`；缺失时再让用户粘贴。
- **岗位薪资范围或期望月薪**（用于判定高级/中级，规则见 SKILL.md：**>15k/月 = 高级**）；也可从 `jd.md` 中的薪资段落读取。
- JD：驻场/外包、技术栈、业务域（GIS、信创等）。
- 偏 Java 后端还是偏运维交付；面试官风格：温和 / 正常 / 略压力。

## 高级工程师：四类侧重（选题时勾选）

| 类别 | 高级追问方向示例 |
|------|------------------|
| **技术深度** | JVM 内存与 GC 思路；线程池参数与拒绝策略；`synchronized` vs `ReentrantLock`；常见设计模式在项目中的落地与反例 |
| **系统设计** | 微服务拆分与一致性；缓存与 DB；消息可靠性与幂等；限流降级位置；分库分表何时上 |
| **项目经验** | 难点归属、你的决策依据、若重来如何改、量化结果 |
| **问题解决** | 一次线上/性能/数据问题的完整链路：现象 → 工具 → 根因 → 修复 → 预防 |

**高级**：每个技术主题块在「介绍」之后，**2～3 个**层层递进追问；项目段 **2～3 个**深挖锚点。

## 中级工程师

- 同一主题块：「介绍」之后 **1～2 个**深入问即可；项目段 **1～2 个**深挖。
- JVM/并发/大规模架构：**最多 1 个小串**，其余时间给 Spring、MySQL、Redis 基础、接口与联调、业务实现。

## 技术块：从「介绍」到「深入」（按 JD/简历选块）

每块流程：**请先介绍你对 X 的理解及在项目中的使用** → 再按职级选追问数量。

### Spring Cloud / 微服务拆分

- 拆分依据？重来会改哪条边界？（高级：CAP、一致性、团队边界）
- 跨服务调用失败如何定位？（高级加：超时、重试、雪崩）
- 与 Dubbo 等选型差异（按 JD）

### Redis

- 场景与过期；穿透/击穿/雪崩（中级到「能说出方案」即可；高级追问实现代价与一致）
- 分布式锁与主从边界（高级）

### Kafka

- Topic/消费者组语义；幂等（高级）；Lag 排查（中高级）

### CAS / 统一认证、信创、文件服务、AI 辅助

- 见旧版追问列表；高级追问**安全、一致、回滚、多租户**；中级追问**流程与对接经验**。

## 项目与业务块

- 开场：**2～3 分钟介绍最有代表性项目**（背景、职责、栈、难点、结果）。
- 高级：必须有一条 **「技术难题或复杂需求」** 的连续追问。
- 业务通用：需求不清如何推进、接口变更约定、上线与运维协作（驻场 JD 加重）。

## 表达结构（提醒候选人）

- 金字塔结论先行；STAR 压缩；不会时：边界 + 补齐计划。
